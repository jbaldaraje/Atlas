# Lightweight runtime, menu bar mode, and performance validation

This increment extends the existing native Vault app in the Atlas repository. It preserves its catalog, file permissions, graph renderer, document explorer, dashboard, appearance, and encrypted vault. Minimum deployment remains macOS 14; Xcode 16+ remains recommended. No third-party runtime dependency or additional entitlement is introduced.

## What the source audit found

Profiling on macOS was unavailable in the cloud environment. The following are source observations, not measured latency or memory improvements:

| Area | Previous source behavior | Implemented change |
|---|---|---|
| Monitoring | Unconditional 30-second timer revisited all enabled roots | One native FSEvents stream per approved root; two-second event coalescing and serialized reconciliation of dirty roots. One initial reconciliation and reconnect/wake reconciliation cover missed changes. No idle scan timer. |
| Progress persistence | Checkpoints encoded/wrote the entire workspace | A separate actor writes atomic `scan-job.json`; in-memory last-scan publication follows the write. The journal contains no document contents. |
| Scan metadata | Every candidate regenerated bookmarks; every nonempty batch rewrote the catalog | Reuse unchanged references with matching identity/size/nanosecond modification and inode-change timestamps. Do not reuse based solely on mtime; zero-nanosecond/coarse change times do not enable the fast path. Existing bookmarks must still resolve without staleness before reuse; renewed references persist even when content metadata is unchanged. Unchanged catalog merges skip saves and revision invalidation. |
| Scan preparation | Catalog merges and organization JSON encoding ran on the main actor | Merge lookup/transform/encoding and organization transform/encoding run in awaited background workers. Revision checks reject stale preparations after user metadata edits. No worker is started per catalog item. |
| UI progress | Import callbacks and organization labels updated for every item | Index/import/analysis callbacks and per-file organization labels use a monotonic 100 ms throttle, with final counts always delivered. Stage and batch boundaries still publish. |
| Thumbnails | Four active requests; fixed 32 MB cache and approximate fixed per-image cost | Preserve four active requests, bound queued requests, allow 16/32/64 MB cache budgets, count decoded pixel costs, size widget thumbnails appropriately, cancel hidden requests, and evict on memory-pressure signals. NSCache cost limits are advisory, not a hard total-process memory limit. |
| Document resources | Bookmark lookup could block the UI; inactive previews could retain resources | A serial background bookmark resolver and immutable scope leases serve previews/thumbnails/open/Finder/watches. Hidden native readers release Quick Look/PDF resources and scopes. PDF find cancellation propagates to the loading worker; synchronous native parsing cannot be interrupted internally. |
| Text/images | UTF-8 extraction and note readers loaded whole text files; OCR loaded full-size NSImage | Bounded UTF-8 reads (1 MiB, extraction capped at 200k characters); note-reader truncation is disclosed with Open Local Copy. ImageIO requests an oriented image with a 4,096-pixel longest side for OCR. Existing PDF input/page/text limits remain. |
| Graph | Already cached, background, 150 nodes / 900 edges with low-zoom detail | Preserve drawing budgets, actual relationships and stable positions; avoid sorting an entire subject's peer IDs for selection context. Hidden windows remove the canvas and mascot scene. Reconstructible graph/catalog/content caches are released when the main window is not visible. |
| Dashboard/search | Bounded widgets existed but could refresh while the window was hidden | Visibility-gated queries cancel hidden preparation. Catalog reconciliation and real-open activity are service-owned so they continue with no workspace window. Dashboard results/snippets and recent-activity arrays can be released. Folder/inspector/explorer/storage preparation also pauses while hidden. Navigation and unsaved metadata/subject editor state remain in their existing views. |
| Exact duplicates | Candidate hashes were recomputed for every analysis | At most 256 in-memory digests per analysis service, keyed by identity plus current change signature. Coarse/missing signatures are not reused. Fresh size, dates, identity and post-read signature are checked; cancellation remains per 1 MiB chunk. No automated deletion is introduced. |

Metadata signatures are conservative filesystem hints, not cryptographic proof against a malicious filesystem or a file changing after analysis. Coarse timestamps, remote volumes and concurrent replacement need native acceptance. Cached hashes are not persisted; disk cleanup retains its explicit inspection, permission and confirmation workflow. All candidate/report data remains a snapshot requiring review.

## Menu bar and window behavior

The native menu bar icon offers Open Vault, Open Knowledge Map, Search Vault, scan status/percentage, Inspect Scan, Pause/Resume/Cancel, explicit Retry of a stopped job, Settings, Hide to Menu Bar and Quit. It contains no document lists, file paths or secure records. A single identified SwiftUI Window is reused; reopening does not launch another process or create duplicate workspace windows.

**Minimize to Menu Bar** is in Settings → Background & performance and defaults to off. When enabled, the red close button hides the workspace instead of destroying it. Standard minimization still minimizes it to the Dock. App Hide hides it normally. Menu actions restore the tracked window, including deminiaturizing it, or open the single workspace if it was genuinely closed. With the setting disabled, the close button keeps normal window closure. Closing a macOS window and explicitly quitting remain different operations: the menu bar and enabled monitoring belong to the running app, even with no workspace window.

Visibility includes minimization, hiding and AppKit occlusion. Expensive presentations stop or release resources while invisible; lightweight navigation and editor state are retained. Security locking still applies on focus/visibility loss. Low Power Mode, serious/critical thermal state, Reduce Motion and existing Cinematic animations preferences restrict decorative effects. The existing Secure Vault boundary is unchanged. No background activity assertion prevents sleep and no launch-at-login service/daemon is installed.

Background monitoring runs at utility priority only when an approved root changes, or during initial/reconnect reconciliation. Its cursor is metadata-first and buffers at most 512 visited entries. Scope/exclusion/category controls remain active. Vault's own Application Support directory is excluded from discovery and event-triggering to prevent indexing its own metadata/secure payloads or creating a self-triggered scan loop. Disconnect/pause removes watchers and scope ownership. Permission/volume failures remain visible in-app; reconnecting an unavailable root can require reapproval or toggling its monitoring. Automatic removal of missing catalog entries is not implemented.

## Scan pause, recovery and quitting

Pause/Resume is available in the progress sheet, compact scan bar and menu. A cooperative continuation gate runs no pause timer. Pause takes effect at file/stage boundaries, including metadata duplicate review; it cannot interrupt an already executing OS copy, PDF parsing, metadata request or filesystem call. Cancel drains paused waiters and retains completed catalog batches. No stopped job reports 100% merely because it stopped.

The authoritative latest job is `scan-job.json` in Application Support/Vault. Older workspace-embedded last-scan records remain the fallback for migration. A running/paused journal is presented as Interrupted after restart. **Retry** starts a fresh enumeration and safe identity-aware merge, reusing unchanged metadata; it does not blindly skip an old directory offset or pretend an interrupted traversal completed. No scan automatically resumes without the user's action after process restart. A corrupt journal is preserved, reported and blocks new scan journal writes until repaired; keep a copy before recovery.

Sleep cooperatively pauses a running manual scan, locks secure content, and stops monitoring streams. Wake reinstalls watchers/reconciles missed changes and resumes only a scan automatically paused for that sleep. A manually paused scan stays paused. Quit cancels scans/imports/Notes requests and waits for supported catalog/recovery operations and final checkpoints/preferences before replying to macOS termination. Existing synchronous native operations may delay that reply; forced termination cannot guarantee final saves. The last durable running checkpoint is recovered as Interrupted. There is no work after the process has quit.

## Quiet notifications

Settings → Notifications provides Off (default), Important events only, and Scan completion and errors. Off neither requests notification authorization nor submits routine notifications. Authorization is requested only when the user selects an enabled option. Optional alerts cover failed scans or completed scans with issues; the completion option also includes clean completion. Cancellation, normal progress, navigation, thumbnails, graph changes, launching and closing do not produce alerts.

Messages use generic app text without source paths, filenames, excerpts or Secure Vault state. macOS permission/settings control delivery; Vault does not override them. Settings displays permission problems, menu status exposes operation issues, and pending in-app alerts are held until the main window is visible. File-access, Notes Automation and authentication permission prompts remain the existing explicit native flows; those are distinct from notifications.

## Actual results and remaining bottlenecks

Attempted commands in this Linux environment:

- `swift test --package-path Packages/VaultCore`: exit 127, `swift: command not found`.
- `xcodebuild -project Vault.xcodeproj -scheme Vault -destination 'platform=macOS' test`: exit 127, `xcodebuild: command not found`.

Static Swift grammar parsing passes for 81 files, project references/exact source membership pass (54 app, 11 core, 27 native integration sources), scheme XML/entitlements parse, and `git diff --check` passes. These do not type-check Swift or verify framework APIs. Added 14 regression methods: four package policies/freshness/progress/event-coalescing tests and ten native tests for pause cancellation, journal recovery/corruption, hash freshness, unchanged synchronization, invalid bookmark renewal, stale preparation rejection, cache release, actual FSEvents delivery, and cancelled preview resolution. The full 73 package and 62 native methods remain unrun here. No app launch, Instruments session, successful native build, before/after measurement, fixed memory guarantee or verified speedup is claimed.

Remaining costs include full JSON loading at startup, main-actor reconciliation/metadata editing, synchronous final atomic file replacements, and separate catalog/workspace writes rather than one cross-file transaction. Large native copies/PDF parsing/filesystem requests cannot be forcibly cancelled mid-call. The existing Apple Notes NSAppleScript bridge remains main-thread and can wait for its bounded Automation timeout. The entire catalog and opted-in text index still reside in memory; this update does not implement a disk-paged database or incremental per-path FSEvents journal replay. Real filesystem event behavior, AppKit window-delegate forwarding, sandbox grants, notification settings, forced termination, GPU/energy use, and resource release require signed macOS validation.

## Reproducible profiling on a Mac

Use a disposable macOS account and disposable source trees. Do not benchmark against or delete a personal Vault database or real originals. Preserve signing identity for each fixture install. Compare baseline commit `28fc5e2` with this change using separate worktrees/fixture app data, the same Mac, macOS, Xcode, display, power mode and file tree. First-run indexing and warm-cache browsing should be reported separately. Use 1k, 10k and 30k+ entries, a substantial image set, a large supported PDF, unsupported/locked files and a dense graph. Existing large graph/catalog test fixtures can supplement actual indexed test trees; they are not runtime measurements.

1. Build Release for both revisions and run the README's package/native tests. Profile the signed application with Product → Profile. Use Time Profiler, Allocations/Leaks, Swift Concurrency, Memory Graph and Animation Hitches as appropriate. Activity Monitor adds CPU, memory, disk and Energy Impact. Record tool versions and hardware.
2. Measure idle after launch and after indexes settle, scan peak memory/throughput, screen first-open latency, warm search latency, graph pan/zoom/selection frame time, and time from Cancel until the job stops. Repeat five times and report the median/range with scope and cache conditions.
3. Open/close the same large preview repeatedly. Inspect retained PDFDocument/QLPreviewView/NSImage instances and security-scope/stream ownership in Memory Graph. Check that closing/minimizing removes native preview/render work and no dashboard query loop remains hidden.
4. Leave the app visible and then hidden in menu mode for 60 seconds with no file changes. Verify no 30-second directory traversals occur. Write bursts into one approved root and verify coalescing, correct category/exclusion behavior and only relevant-root reconciliation. Test root rename, permission loss, external-volume disconnect/reconnect, excluded paths, overlapping roots, and FSEvents overflow/root-change signals. Retry/reconnect must preserve originals.
5. During scanning, browse/search/resize/preview/pan, pause/resume, minimize/close/reopen, hide/unhide, and quit. Verify one workspace/process, preserved editor drafts, accurate counters, durable completed batches, and no dropped or falsely completed work. Test sleep/wake and forced termination on fixtures. Check notification Off produces no authorization prompt; enabled options obey authorization/denial and submit only qualifying terminal events.
6. Inspect synchronous JSON writes/reconciliation and the Notes Automation timeout in Time Profiler. If these dominate, use those measurements to justify the next persistence/async-bridge migration instead of claiming the current version solves every stall.

Record a table for each library/hardware configuration: idle RSS/CPU, scan peak RSS/files-per-second, graph RSS/frame-time, first-open/search latency, cancel latency, hidden CPU/disk activity, post-preview memory and interrupted recovery. Baseline and updated values are **pending**. Set regression budgets only after gathering those measurements; this source change supplies structural limits, not universal timing or memory targets.
